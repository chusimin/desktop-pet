# 从零 vibe 出一只桌面宠物 · 全流程复现手册

> 你（产品 / 设计，**不写代码**）指挥 Claude Code，从一套动作素材做出一只会休息、会跟你聊天、能听你说话、喊一声就来、还能帮你干活、最后能打包送人的桌面宠物。
>
> 本手册把「多吉」（一只 macOS 像素柯基）的全过程**抽象成可换皮的通用配方** —— 换成你的猫 / 兔 / 任意角色素材，同一套步骤照走。每一步都给出**可直接粘贴的提示词**和**怎么验收**。

---

## 这份手册怎么用

**你需要准备：**
- 一台 Mac + [Node.js](https://nodejs.org)（18+）+ 已装好的 Claude Code（终端里能跑 `claude`）
- **一套动作帧素材**（本手册的前提，见第 0 步）
- （可选）一个大模型 API Key —— 只有「聊天 / 语音 / 笔记问答」用得上，纯桌宠不需要

**怎么读：**
- **正文** 是给会指挥 AI 的产品 / 设计看的：照着每一步，把🗣提示词粘给 Claude Code，再按 ✅验收点 检查。
- 折叠的 **🔧 技术档** 是给开发者看的原理与踩坑，不想看可以全跳过，不影响复现。

**贯穿全程的方法 ——「驾驭工程」：**
> 你只负责**提需求**和**验收**，AI 负责写代码。每个功能都是一个闭环：
> **开发 → 让 AI 自己测 → 你看一眼验收 → 立即提交（git commit）**。
> 一次只做一个功能，做完就存档，永远可回滚、可追溯。这是整套流程能稳的根。

## 第 0 步 · 把素材准备成「程序能用」的样子

> 前提：你已经有整套动作图（走 / 待机 / 挠头 / 叫 / 打滚……）。这一步不是画图，是**让一堆图变成代码能稳定调用的素材**。

🗣 **提示词：**
```
我有一只桌面宠物的整套动作帧（PNG，透明背景），每个动作一个文件夹，
里面是按顺序编号的帧。帮我建一个 Electron 项目骨架，并写一个素材归一化脚本：
把所有帧统一到同一张正方形画布、对齐到同一条「地面基线」，导出到 assets/<动作名>/。
告诉我每个动作文件夹该怎么命名、每帧怎么编号，你按这个约定来加载。
```

✅ **验收：** Claude 给你一套**命名约定**（比如 `assets/walk/0.png … 8.png`），并且归一化后所有动作叠在一起脚是踩在同一条线上的（不会有的悬空有的陷地）。

<details>
<summary>🔧 技术档：基线对齐 + 一个真实的坑</summary>

- **统一画布 + 基线对齐**是关键：每个动作帧尺寸不一，必须缩放到同一画布、底部对齐到固定 baseline，切换动作时脚才不会跳。
- **真实踩坑（眼睛帧）：** AI 生成的"眼睛看不同方向"的帧**自身就不一致**（同一帧里两只眼睛可能朝不同方向），靠角度算朝向怎么都反。**解法：按方向给素材重命名**（右 / 右上 / 上 / 左上……），代码再用「狗→鼠标」向量的**余弦相似度**挑最接近的那张。**经验：当一类素材有方向/状态语义时，把语义写进文件名，别让代码去猜。**
</details>

## 第 1 步 · 骨架 + 会动会拖

🗣 **提示词：**
```
用 Electron 做一个 macOS 桌面宠物：一个透明、无边框、始终置顶的小窗口，
里面用 canvas 逐帧播放 assets/ 里的动作动画。要求：
1. 窗口背景完全透明，只看得到宠物本体；
2. 可以用鼠标 1:1 拖动它到屏幕任意位置；
3. 宠物身体之外的透明区域，鼠标点击要能"穿透"到下面的应用（像素级穿透）。
先实现这三点，然后启动给我看。
```

✅ **验收：** 桌面上出现宠物、能拖；点它旁边的空白处，点到的是底下的应用（不是被这个窗挡住）。

<details>
<summary>🔧 技术档</summary>

- 透明 + 无边框 + `alwaysOnTop`；`setIgnoreMouseEvents(true, {forward:true})` 默认穿透，渲染层用 canvas 的 **alpha 命中检测**判断鼠标是否真在身体不透明像素上，是才临时关掉穿透。
- 拖动的 grab 偏移要**同步**算好（别等异步 `getPos`），否则第一帧会跳。
</details>

## 第 2 步 · 让它「活」起来

🗣 **提示词：**
```
让宠物像活物，而不是一张贴纸：
1. 大约一半时间在"休息"，休息时有轻微的呼吸起伏；
2. 休息时眼睛跟着我的鼠标转（鼠标在哪它看哪）；
3. 偶尔做个小动作（挠头/叫/打滚），然后回到休息。
```

✅ **验收：** 不碰它时它自己呼吸、眼神随鼠标移动；隔一会儿做个小动作又趴下。

<details>
<summary>🔧 技术档</summary>

- 主进程每 ~33ms 读全局光标 `screen.getCursorScreenPoint()` 推给渲染层定注视方向。
- 眼睛帧按方向命名 + 余弦相似度选帧（见第 0 步的坑）。**客观验收法**：往八个方向各放一次光标、截图、和命名素材像素比对，别靠肉眼看瞳孔。
</details>

## 第 3 步 · 行为打磨（这步全靠"给约束"）

> 这一步最能体现 vibe 的精髓：**你描述想要的"行为约束"，不告诉它怎么实现。**

🗣 **提示词（我的真实原话，照搬即可）：**
```
1. 把宠物缩小一点，别占太大地方；
2. 允许它走动，但不要走太远，走了以后要回原地；
3. 固定悬浮在任何应用之上（包括全屏应用）。
```
然后追加这条（也是真实原话，修走路姿态）：
```
走动只能横着走，别上下斜着走（走路素材是侧面的，斜着滑很怪）；
可以稍微走远一点，再走回来。
```

✅ **验收：** 它在"家"附近左右溜达、走完自己走回原位、不会越走越远；切到全屏应用它还在最上层。

<details>
<summary>🔧 技术档</summary>

- 置顶用 `'screen-saver'` 窗口层级 + 跨空间可见，压得住全屏 app。
- 溜达目标锚定在 **home**（不是当前位置），每次都横向、走完先回家再休息——所以永远不漂移。
</details>

## 第 4 步 · 接入 Claude Code 任务状态（选配）

> 让宠物变成你的"AI 任务状态台"：你的 Claude Code 在跑活时，它头顶显示状态，跑完提醒你。

🗣 **提示词：**
```
我想让宠物显示我 Claude Code 的任务状态。用 Claude Code 的 hooks：
任务开始/结束时，让它 curl 一个本地端口，主进程起一个 HTTP 监听接收，
然后在宠物头顶显示一枚小胶囊。要求监听我这台机器上"所有项目"的会话。
```
⚠️ **重要提醒（我踩过的反转）：** 一开始我让它做"进度条"，但发现没法估真实进度。于是改成下面这条——**这是个好的提示词示范：发现方向不对，果断推翻：**
```
显示进度不太好，因为不确定进度到底多少，只能判断它"还在不在跑"。
就改成：只显示"还在执行"还是"执行成功"。执行成功就显示 ✅，并配合动作汪一下。
```

✅ **验收：** 在任意项目跑一个 `claude` 任务，宠物头顶亮起"在跑"；任务结束变 ✅ 并叫一声。

<details>
<summary>🔧 技术档</summary>

- hooks 注册到 `~/.claude/settings.json`（全局）即可监听全机所有项目；主进程对（事件, 会话）做 600ms 去重，避免重复触发。
- **诚实原则：** Claude Code 没有真实百分比，所以只声称你真知道的事（在跑 / 完成）。**别让 UI 假装知道它不知道的东西。**
</details>

## 第 5 步 · 接入对话（选配）

🗣 **提示词：**
```
让我双击宠物身体打开一个聊天卡片，能和它对话。接 OpenAI 兼容的大模型 API
（先用某家）。要求：
- API Key 放在本地配置文件里，绝不写进代码、绝不进 git；
- 给它一个"宠物人设"，回复简短、口语、有点可爱；
- 请求在主进程发，Key 不进渲染层。
```

✅ **验收：** 双击它弹出聊天框，能正常一问一答，语气符合人设。

<details>
<summary>🔧 技术档 + 一个性格坑</summary>

- Key 放 gitignore 的本地 `config.json`，提供 `config.example.json` 模板；请求在主进程发。
- **真实坑：** 便宜模型扮演"粘人宠物"时爱**瞎编**（"我刚翻了你的笔记《xxx》"）。软性"别编造"没用，要写**硬条件**：「只有消息里真附了笔记片段才能提笔记，否则绝不提任何笔记名」——瞎编率直接归零。
</details>

## 第 6 步 · 用你的笔记回答（选配）

🗣 **提示词：**
```
我有一个本地知识库（一堆 markdown 笔记）。每次我问问题时，先在本地检索
最相关的几段笔记，作为参考喂给模型，让它优先据此回答、并说出处自哪篇；
没检索到就老实说没找到。全程本地，不建索引、不联网。
```

✅ **验收：** 问一个只有你笔记里才有的事，它能引用到对应笔记内容并报出标题。

<details>
<summary>🔧 技术档</summary>

- 轻量本地 RAG：中文双字（bigram）+ 文件名加权检索，取 top 几段拼成参考。500 篇笔记扫描在一秒内，无需向量库。换皮时把"笔记库"换成任何文本资料目录即可。
</details>

## 第 7 步 · 语音输入（选配）

🗣 **提示词（我的真实原话）：**
```
帮我接入一个语音转文字模型，我跟宠物说话，它用文字气泡回复我
（先语音转文字，再大模型理解加回复）。
```
再加全局快捷键（真实原话）：
```
我想设置一个快捷键，长按唤出语音，松手自动发送并转文字。
```

✅ **验收：** 聊天框里按住录音、松手后它把你说的话转成文字并回复；在任意应用里长按快捷键也能说。

<details>
<summary>🔧 技术档</summary>

- 录音 → 重采样 16k 单声道 WAV → 转写模型 → 转写文本走正常聊天链路。
- 全局快捷键只有"按下"没有"松开"事件，所以"松手"靠弹出的聊天窗监听 keyup；预创建隐藏聊天窗保证弹出零延迟。
</details>

## 第 8 步 · 离线语音唤醒（进阶）

> 喊一声名字就免按键唤起对话。**全程本地离线**，不联网、不耗 API、不上传音频。

🗣 **提示词：**
```
我想实现语音关键词唤醒：我喊"<宠物名字>"，它就自动开始听我说话、然后回答。
唤醒词识别要在本机离线完成，不联网、不上传音频。听到唤醒词后：
先做个动作（叫一声），再弹出对话开始聆听，我说完停顿一下就自动发送。
```
加点情绪价值（真实原话，很出彩）：
```
唤醒的时候，动作上先叫一声，然后冒个小气泡回复我一下：
"主人，你终于想起我了"（随机几句）。
```

✅ **验收：** 喊名字 → 它叫一声 + 弹出随机问候 + 开始听；你说完停顿约 1 秒自动转写发送。

<details>
<summary>🔧 技术档（这步最硬）</summary>

- 用 **sherpa-onnx**（离线关键词检测）+ 中文 KWS 模型（约 5.5MB）。一个隐藏窗采麦克风 → 16k PCM 串流给主进程做检测。
- 唤醒后用**能量 VAD**（音量检测）判断你说完了：检测到开口、再检测到约 1.2s 静音就自动停。
- 自定义唤醒词是**拼音 token**（不是汉字），靠合成/真人语音实测验证别瞎写。
- 隐藏窗的 AudioContext 需要 `autoplay-policy=no-user-gesture-required` 才会跑。
- **打包坑：** 原生 `.node` + 它的 `.dylib`、模型文件必须解包出 asar，且 `.node` 与 dylib 要在同一目录靠 `@loader_path` 解析。
</details>

## 第 9 步 · 拖文件起终端（进阶）

> 把文件夹拖给宠物，它"吃"进去并自动开终端、`cd` 过去拉起 Claude Code。

🗣 **提示词（我的真实原话）：**
```
拖拽一个文件或文件夹给它的时候，可以自动打开终端、调用起终端里的 Claude Code、
自动载入这个文件/文件夹，可以开始对话。落下时给个"吃进去"的动画反馈。
```
⚠️ 如果一开始拖了**没反应**，把现象告诉 AI（这也是真实发生的）：
```
拖文件到宠物身上没反应，文件夹直接被忽略了，你先排查问题。
```

✅ **验收：** 从访达拖个文件夹到它身上 → 它张嘴吃进去 → 终端自动打开并在那个目录跑起 `claude`。

<details>
<summary>🔧 技术档（一个反直觉的系统级坑）</summary>

- **根因：** macOS 对**配置过点击穿透（setIgnoreMouseEvents）的窗口，永远不再派发拖拽事件**——事后解除穿透也救不回来。
- **解法：** 一个 python 子进程盯住系统拖拽状态，一旦开始拖文件，就在宠物位置弹一个**从未穿透过的隐形"接驳窗"**接住投放，再转交给宠物。
- **方法论：** 遇到"应该有反应却没反应"，用**二分对照**定位——做一个对照窗口对比，一步步缩小到底哪一环断了。
</details>

## 第 10 步 · 打包成独立 App（收尾）

🗣 **提示词（真实原话）：**
```
帮我打包成一个 app，不然关机以后下次怎么打开。要双击就能启动、开机自启。
```

✅ **验收：** 双击 App 启动；重启电脑后它自己出现；不占 Dock。

<details>
<summary>🔧 技术档</summary>

- 用 `@electron/packager` + asar 打包；配置文件放用户目录（App Support），打包体只读。
- 首次运行自动登记开机自启（菜单可关）；单实例锁防止开出两只。
- 打包脚本**按当前芯片自适应**（Apple Silicon / Intel），别写死，朋友才能直接用。
- 麦克风等权限要在打包配置里声明（`NSMicrophoneUsageDescription`），否则打包版一碰麦克风就被系统杀掉。
</details>

## 第 11 步 · 稳定性收尾（收尾，别省）

> "能跑"和"能一直跑"是两回事。这两条让它经得住日常使用。

🗣 **提示词（防崩）：**
```
让它永远不要因为一个异常坐标就崩溃/弹报错框。任何移动窗口的地方，
遇到非法数值就丢弃那一帧并自愈，不要让整个 app 挂掉。
```
🗣 **提示词（修锁屏错位，真实原话）：**
```
为什么它老是有 bug、位置会错乱，尤其容易发生在我锁屏又打开的时候？
```

✅ **验收：** 连续用一天不弹报错；锁屏再打开，宠物还在原位、点击穿透和眼神都正常。

<details>
<summary>🔧 技术档</summary>

- **锁屏错位根因：** 渲染层只在启动时记一次自己的位置，而 macOS 在显示器睡眠/唤醒时会悄悄挪窗口——之后它还以为在老地方，注视、穿透、走动全错。
- **解法：** 监听 `powerMonitor`（resume/unlock）和显示器变化事件，唤醒时把窗口**夹回可见区 + 把真实坐标推给渲染层重新校准**；锁屏期间让走动停摆。
</details>

## 🧭 驾驭工程心法（可迁移到任何 vibe 项目）

这套打法和"做桌宠"无关，是**指挥 AI 做任何产品**都通用的：

1. **原子化交付。** 一次只做一个功能，做完 → AI 自测 → 你验收 → 立即 git commit。每一步可测、可回滚、可追溯。这是不翻车的根。
2. **给约束，不给实现。** 说"走了不要走太远、要回原地"，别说"用 setInterval 加边界判断"。你定**要什么**和**不要什么**，让 AI 决定怎么写。
3. **先展示，再扩展。** 拿不准就先让它"启动给我看一下 / 先做一个验证"，看到真东西再决定方向。
4. **敢推翻。** 方向不对就明确推翻（我把"进度条"推翻成"诚实状态"）。沉没成本不值钱，对的方向才值钱。
5. **让 AI 自己验证。** 要求它**客观验收**而不是嘴上说"做好了"：截图给自己看、注入合成事件、合成测试音频、二分对照定位。**口说无凭，要它拿证据。**
6. **报现象，不报方案。** 出 bug 时描述**现象 + 触发条件**（"位置错乱，尤其锁屏后"），这比你猜一个错误的原因更能帮它定位。
7. **产品细节带情绪价值。** "唤醒时先叫一声、再冒句'主人你终于想起我了'"——这种小设计花不了多少功夫，却是宠物"活"的关键。

## 🏗 技术附录：架构总览 + 4 个硬骨头（给开发者）

**架构一句话：** Electron 主进程管"特权操作"（窗口、全局光标、系统集成、API Key），渲染层只画画 + 命中检测，两者经 preload 白名单 IPC 通信（`contextIsolation` 开、`nodeIntegration` 关）。

**4 个最值得记的硬骨头：**

| 难题 | 难在哪 | 怎么破 |
|---|---|---|
| 眼睛老看反 | AI 生成的眼睛帧自身不一致 | 按方向重命名素材 + 余弦相似度选帧 |
| 拖文件没反应 | 穿透过的窗口被 macOS 永久剥夺拖拽事件 | 隐形"接驳窗"接住 + python 监视拖拽状态 |
| 打包后原生模块加载不了 | `.node` + dylib 在 asar 里加载失败 | 解包出 asar + `@loader_path` 自解析 + 打包脚本自校验 |
| 锁屏后位置错乱 | 渲染层位置只 seed 一次，系统挪窗后不自知 | 监听电源/显示器事件，唤醒时夹回可见区 + 重新校准 |

**一个贯穿始终的验证手法：** 这台开发机没有录屏权限，所以全程不靠截屏，而是用窗口的 `capturePage()` 抓画面自己看 + 一个**测试桥**（注入合成光标 / 合成 hook 事件 / 合成语音 / 模拟拖拽）来客观验证每个功能。**没有"人在场"也能自测，是 AI 能独立闭环的关键。**
