# 从零 vibe 出一只桌面宠物 · 全流程手册

> 你（产品 / 设计，**不写代码**）指挥 Claude Code，从一张精灵图做出一只属于你的桌面宠物。
>
> **怎么用这份手册：** 先下载素材包 → 跟着「基础操作」做出一只会动会拖的活宠物（人人都能完成）→ 再从「进阶模块」里**挑你想要的能力**自己加（眼神跟随 / 跟它聊天 / 听你说话 / 喊名字唤醒 / 拖文件帮你干活……做到哪算哪）→ 最后看「自由探索」加点小花样，做成独一无二的它。

---

## 写在前面 · 这是什么，为什么是它

你大概已经用 AI 生成过不少东西了——画图、写文案、做 PPT、改简历。但有没有那么一个时刻，你会想：这些都是「碎片」，我能不能用 AI 真正**做出一个完整的、能跑起来的东西**？一个不是交付物、而是**作品**的东西？

这个案例，就是为这个时刻准备的。

**我们要一起做的，是一只住在你电脑桌面上的宠物。**

它会安安静静趴在屏幕角落、轻轻呼吸；你移动鼠标，它的眼睛跟着你转；你能把它拖到任何地方，点它一下它会「汪」地叫一声。往深里做，它还能跟你聊天、听你说话、你喊一声名字它就跳起来回应你，甚至你把一个文件夹拖给它，它「吃」进去就帮你把活儿开起来。

但说实话，这只宠物本身不是重点。**重点是：它是你「指挥 AI」做出来的第一个真东西。** 从一张素材图，到一个能双击启动、能送给朋友用的桌面应用——这条从 0 到 1 的完整的路，你会第一次完整地走一遍。

### 为什么是「桌宠」，而不是别的

带大家入门，我挑了很久，最后选了它。因为对**设计师、和喜欢捣鼓新东西的人**来说，桌宠几乎是最理想的第一个案例：

- **它看得见、有反馈。** 你不是在跑一段看不见的脚本，而是眼睁睁看着一个小东西在屏幕上「活」过来。设计师是用眼睛思考的，这种即时又可爱的反馈，是最好的动力。
- **门槛低，上限高。** 基础版一个下午就能做出来，不会有人卡在「第一步」；但它能一直往上加（语音、AI、唤醒、打包），又不会有人撞到天花板。**你自己决定做到哪一步。**
- **它是「你的」。** 换上你喜欢的角色、给它起个名字、调一句它的口头禅——它有归属感。不是做完就扔的练习题，而是你会真的留下来天天用的东西。
- **它既可爱又有用。** 它能帮你盯 AI 任务、陪你工作。这件事本身在证明一件事：**AI 做出来的东西，可以有温度，不只是有功能。** 而这，恰恰是设计师最该相信、也最能做到的。

### 为什么是你

你可能不会写代码。没关系——**这个案例从头到尾，你一行代码都不用写。**

代码是 AI 写的。你要做的是另一件事：**提需求、做判断、定方向、验收。** 哪里不对、想要什么效果、可不可爱、好不好用——这些 AI 没有判断力的地方，正是你有判断力的地方。

我把这套打法叫**「驾驭工程」**：你不需要变成工程师，你需要学会**指挥**一个工程师。设计师的审美、产品人对需求的敏感、对「体验好不好」的直觉，恰恰是驾驭 AI 时最稀缺、最值钱的东西。这个案例，就是把你**已经有**的这些长处，第一次变成一个真的能跑的产品。

### 你会带走什么

做完这一个，你带走的不只是一只宠物：

- **一个你亲手「指挥」出来、还在天天用的作品**——能发给朋友、能发朋友圈；
- **一套可迁移到任何东西的方法**——学会了怎么带 AI 做桌宠，你下一个想做的（工具、网站、插件……）是同一条路；
- 以及最重要的：**那句「原来我也能做出东西」的笃定。**

这是我们一起做的**第一个**案例。把它做出来，你就会明白：**「想做」和「能做」之间，那道墙已经塌了。** 🐾

## 开始之前

**准备好：**
- 一台 Mac + [Node.js](https://nodejs.org)（18+）+ 已装好的 Claude Code（终端里能跑 `claude`）
- **下载素材包**：一个文件夹，里面是 `spritesheet.webp`（一整张精灵图）+ `pet.json`（宠物信息）
- （可选）一个大模型 API Key —— 只有「聊天 / 语音 / 笔记问答」模块用得上，纯桌宠不需要

**怎么读：**
- **正文**给会指挥 AI 的产品 / 设计：把🗣提示词粘给 Claude Code，再按 ✅验收点 检查。
- 折叠的 **🔧 技术档**给开发者，不看也能照做。

**贯穿全程的方法 ——「驾驭工程」：**
> 你只提**需求**和**验收**，AI 写代码。每个功能一个闭环：**开发 → 让 AI 自己测 → 你看一眼验收 → 立即提交**。一次只做一个，做完就存档，永远可回滚。

**素材长什么样（重要）：**
- `spritesheet.webp` 是一张**精灵图**：把宠物的几十个动作帧拼在一张大图里，按**网格**排列（这套素材是 **6 列**、每帧约 **256px** 宽、约 8–9 行不同姿势：站立 / 走 / 挥手 / 坐下……）。
- `pet.json` 很简单，只记了名字和图片路径，**没有记网格怎么切**。
- 所以**第一件事**就是让 Claude Code 帮你「把这张图切成帧、认出每一行是什么动作」—— 这正是下面第 1 步。
- 想换成你自己的角色？把 `spritesheet.webp` 换成你的精灵图即可，步骤完全一样（**换皮通用**）。

# 第一部分 · 基础操作（必做）

> 做完这三步，你就有一只透明窗里、会待机会溜达、能拖能穿透、悬浮在所有应用之上的宠物。**到这儿它已经是一只能用的桌宠了。**

## 1. 把精灵图变成会动的宠物

🗣 **提示词：**
```
我在做一个 macOS 桌面宠物。素材是一张精灵图 spritesheet.webp（多个动作帧拼成的大图，
大约 6 列网格、每帧 256px 左右宽）和一个 pet.json。请：
1. 建一个 Electron 项目骨架，一个透明、无边框、始终置顶的小窗口；
2. 帮我把精灵图按网格切成帧，并认出每一行大概是什么动作（站立/走/坐/挥手等），
   告诉我你的切分结果；
3. 先用 canvas 实现最简单的"待机循环播放"，启动给我看。
```

✅ **验收：** 桌面上出现你的宠物，在循环播放待机动作；Claude 告诉了你它把图切成了几行几列、每行是什么动作（先对一眼，错了就让它改）。

<details>
<summary>🔧 技术档</summary>

- 精灵图切帧：`drawImage` 从大图里按 `(列×帧宽, 行×帧高)` 抠出每一帧。pet.json 没给网格，所以让 Claude 从图像分析切分 + 命名，比你手填坐标省事。
- 透明 + 无边框 + `alwaysOnTop`；窗口内画布按设备像素比放大保持像素清晰。
</details>

## 2. 会拖、能穿透

🗣 **提示词：**
```
让宠物：
1. 可以用鼠标 1:1 拖到屏幕任意位置；
2. 身体之外的透明区域，点击要"穿透"到下面的应用（只有不透明的身体能被点中）。
```

✅ **验收：** 能拖动它；点它旁边的空白，点到的是底下的应用，不是被这个窗挡住。

<details>
<summary>🔧 技术档</summary>

- `setIgnoreMouseEvents(true,{forward:true})` 默认穿透；渲染层用画布 **alpha 命中检测**判断鼠标是否真在身体不透明像素上，是才临时关穿透。拖动的 grab 偏移要同步算，否则第一帧会跳。
</details>

## 3. 让它「活」起来（活宠物的最小集）

🗣 **提示词：**
```
让宠物像活物而不是贴纸：
1. 大约一半时间待机，待机时有轻微的呼吸起伏；
2. 偶尔随机做个小动作（走两步 / 挥手 / 坐下），然后回到待机；
3. 允许它在原地附近溜达，但别走太远、走完要自己走回原位；走动横着走。
另外固定悬浮在任何应用之上（包括全屏应用）。
```

✅ **验收：** 不碰它时它自己待机、偶尔动一下；在小范围溜达又走回原位、不会越走越远；切到全屏应用它还在最上层。

> 🎉 **基础完成！** 你已经有一只讨喜的桌宠了。下面所有能力都是**可选的**——按兴趣挑，不想做可以直接跳到「第三部分」加点小花样，或者就这样用着。

## 👀 模块 · 眼神跟随

🗣 **提示词：**
```
让宠物待机时眼睛跟着我的鼠标转：鼠标在它哪个方向，它就往哪看；鼠标贴近时看向正前方。
```

✅ **验收：** 不碰它，把鼠标在它四周移动，它的视线跟着你走。

<details>
<summary>🔧 技术档（一个真实的坑）</summary>

- 主进程每 ~33ms 读全局光标推给渲染层定方向。
- **坑：** 如果你的精灵图里"看不同方向"的眼睛帧自身不一致（AI 生成素材常见），靠角度算朝向会反。**解法：按方向给这些帧命名**（右/右上/上…），再用「宠物→鼠标」向量的**余弦相似度**挑最接近的那张。验收别靠肉眼看瞳孔，往八个方向各放一次光标、截图比对。
</details>

## 🤖 模块 · Claude Code 任务状态台

> 让宠物变成你的"AI 任务状态台"：Claude Code 跑活时它头顶显示状态，跑完提醒你。

🗣 **提示词：**
```
我想让宠物显示我 Claude Code 的任务状态。用 Claude Code 的 hooks：任务开始/结束时
curl 一个本地端口，主进程起 HTTP 监听接收，在宠物头顶显示一枚小胶囊。
要求监听我这台机器上"所有项目"的会话；只显示"还在跑"还是"已完成"，
完成时显示 ✅ 并让宠物叫一声。
```

✅ **验收：** 在任意项目跑一个 `claude` 任务，宠物头顶亮"在跑"；任务结束变 ✅ 并叫一声。

<details>
<summary>🔧 技术档 + 一个值得学的反转</summary>

- hooks 注册到 `~/.claude/settings.json`（全局）即可监听全机；对（事件,会话）做 600ms 去重防重复。
- **诚实原则（我踩过的反转）：** 一开始我让它做"进度条"，但 Claude Code 没有真实百分比，估不准。于是推翻成"只显示在跑/完成"。**别让 UI 假装知道它不知道的东西——发现方向不对，果断推翻。**
</details>

## 💬 模块 · 对话聊天（需 API Key）

🗣 **提示词：**
```
让我双击宠物身体打开一个聊天卡片跟它对话，接 OpenAI 兼容的大模型 API。要求：
- API Key 放本地配置文件，绝不写进代码、绝不进 git，给一个 config.example 模板；
- 给它一个"宠物人设"，回复简短、口语、可爱；请求在主进程发，Key 不进渲染层。
```

✅ **验收：** 双击它弹聊天框，能一问一答，语气符合人设。

<details>
<summary>🔧 技术档 + 一个性格坑</summary>

- Key 放 gitignore 的本地 `config.json`，请求在主进程发。
- **坑：** 便宜模型扮演"粘人宠物"时爱**瞎编**（"我刚翻了你的笔记…"）。软性"别编造"没用，要写**硬条件**：「只有消息里真附了资料才能引用，否则绝不提」——瞎编率归零。
</details>

## 📓 模块 · 用你的笔记回答（依赖：对话）

🗣 **提示词：**
```
我有一个本地知识库（一堆 markdown）。每次我问问题时，先在本地检索最相关的几段
作为参考喂给模型，让它优先据此回答、并说出处自哪篇；没检索到就老实说没找到。
全程本地、不建索引、不联网。
```

✅ **验收：** 问一个只有你笔记里才有的事，它能引用到对应内容并报出标题。

<details>
<summary>🔧 技术档</summary>

- 轻量本地 RAG：中文双字 + 文件名加权检索，取 top 几段拼成参考，无需向量库。换皮时"知识库"可换成任何文本资料目录。
</details>

## 🎤 模块 · 语音输入（依赖：对话）

🗣 **提示词：**
```
帮我接入语音转文字：我跟宠物说话，它用文字气泡回复我（先语音转文字，再大模型理解回复）。
聊天框里按一下开始录、再按一下结束。再加一个全局快捷键：长按唤出语音、松手自动发送并转文字。
```

✅ **验收：** 聊天框按住录音、松手转文字并回复；任意应用里长按快捷键也能说。

<details>
<summary>🔧 技术档</summary>

- 录音 → 重采样 16k 单声道 WAV → 转写模型 → 转写文本走正常聊天链路。
- 全局快捷键只有"按下"没有"松开"事件，"松手"靠弹出的聊天窗监听 keyup；预创建隐藏聊天窗保证零延迟。
</details>

## 🎙 模块 · 离线语音唤醒（依赖：语音输入）

> 喊一声名字就免按键唤起对话。**全程本地离线**，不联网、不耗 API、不上传音频。

🗣 **提示词：**
```
我想实现语音关键词唤醒：我喊"<宠物名字>"，它就自动开始听我说话、然后回答。
唤醒词识别要在本机离线完成，不联网、不上传音频。听到唤醒词后：先叫一声，
再弹出对话开始聆听，我说完停顿一下就自动发送。唤醒时还冒一句随机问候。
```

✅ **验收：** 喊名字 → 它叫一声 + 冒随机问候 + 开始听；你说完停顿约 1 秒自动转写发送。

<details>
<summary>🔧 技术档（这步最硬）</summary>

- 用 **sherpa-onnx**（离线关键词检测）+ 中文 KWS 模型（约 5.5MB）。隐藏窗采麦克风 → 16k PCM 串流给主进程检测。
- 唤醒后用**能量 VAD**（音量检测）判断说完没：检测到开口、再检测到约 1.2s 静音就自动停。
- 自定义唤醒词是**拼音 token**（不是汉字），靠真人/合成语音实测验证别瞎写；隐藏窗 AudioContext 需 `autoplay-policy=no-user-gesture-required`。
- **打包坑：** 原生 `.node` + dylib + 模型必须解包出 asar，且 `.node` 与 dylib 同目录靠 `@loader_path` 解析。
</details>

## 📂 模块 · 拖文件起终端

> 把文件夹拖给宠物，它"吃"进去并自动开终端、`cd` 过去拉起 Claude Code。

🗣 **提示词：**
```
拖一个文件或文件夹给宠物时，自动打开终端、cd 过去、拉起 claude，可以开始对话。
落下时给个"吃进去"的动画反馈。
```
⚠️ 若一开始拖了**没反应**（真实会发生），把现象告诉它：
```
拖文件到宠物身上没反应，文件夹直接被忽略了，你先排查问题。
```

✅ **验收：** 从访达拖个文件夹到它身上 → 它张嘴吃进去 → 终端自动开并在那个目录跑起 `claude`。

<details>
<summary>🔧 技术档（反直觉的系统坑）</summary>

- **根因：** macOS 对**配置过点击穿透的窗口，永远不再派发拖拽事件**，事后解除也救不回来。
- **解法：** 一个 python 子进程盯系统拖拽状态，开始拖时在宠物位置弹一个**从未穿透过的隐形"接驳窗"**接住投放，再转交。
- **方法论：** "应该有反应却没反应"，用**二分对照**（做个对照窗口对比）一步步缩小到哪一环断了。
</details>

# 第三部分 · 再加点小功能 · 自由探索

## 🧭 驾驭工程心法（可迁移到任何 vibe 项目）

1. **原子化交付。** 一次只做一个功能：开发 → AI 自测 → 你验收 → 立即提交。可测、可回滚、可追溯。
2. **给约束，不给实现。** 说"别走太远、要回原地"，别说"用 setInterval 加边界判断"。你定**要什么/不要什么**，让 AI 决定怎么写。
3. **先展示，再扩展。** 拿不准就先让它"启动给我看一下"，看到真东西再决定方向。
4. **敢推翻。** 方向不对就明确推翻（我把"进度条"推翻成"诚实状态"）。
5. **让 AI 自己验证。** 要它**拿证据**（截图、日志、合成事件测试），别只听它说"做好了"。
6. **报现象，不报方案。** 出 bug 时描述**现象 + 触发条件**（"位置错乱，尤其锁屏后"），比你猜个错原因更能帮它定位。
7. **细节带情绪价值。** "唤醒时先叫一声、再冒句'主人你终于想起我了'"——这种小设计是宠物"活"的关键。

## 🏗 技术附录：4 个硬骨头（给开发者）

| 难题 | 难在哪 | 怎么破 |
|---|---|---|
| 眼睛看反 | AI 生成的眼睛帧自身不一致 | 按方向命名素材 + 余弦相似度选帧 |
| 拖文件没反应 | 穿透过的窗口被 macOS 永久剥夺拖拽事件 | 隐形"接驳窗"接住 + python 监视拖拽 |
| 打包后原生模块加载不了 | `.node`+dylib 在 asar 里加载失败 | 解包出 asar + `@loader_path` 自解析 + 打包自校验 |
| 锁屏后位置错乱 | 渲染层位置只 seed 一次，系统挪窗后不自知 | 监听电源/显示器事件，唤醒时夹回可见区 + 重新校准 |

**验证手法：** 开发机没录屏权限，所以用窗口 `capturePage()` 抓画面自己看 + 一个测试桥（注入合成光标 / hook 事件 / 语音 / 模拟拖拽）客观自测每个功能——**没有"人在场"也能闭环**。
